# 맵 배포

## 이 문서를 볼 때

맵을 "배포"하거나 "공유"하는 기능을 만들 때 본다. 맵 자체의 방/오브젝트/상호작용 데이터 구조는 [DB와 JSON 구조](./DATABASE_AND_JSON.md)를 참고한다.

## 맵 원본(draft)과 배포본(published) 분리

에디터에서 계속 고치는 대상과 "공유된 맵"은 서로 다른 개체로 다뤄야 한다. 지금 `data/maps.js`는 이 구분이 없이 레코드 하나가 편집·배포·공유를 다 겸하고 있는데, 앞으로는 나눠야 한다.

- **맵 원본(draft)**: 에디터에서 계속 수정하는 대상. 항상 mutable, id 고정.
- **배포본(published snapshot)**: "배포" 버튼을 누른 시점의 스냅샷. 불변. 맵 목록 카드와 실제 플레이(게임방)는 이 배포본을 참조한다.

원본을 고쳐도 이미 배포돼서 플레이 중인 게임방에는 영향이 없다. 다시 배포해야 새 스냅샷이 공개된다. 스타크래프트에서 "맵 파일"(에디터로 계속 고치는 원본)과 "저장된 맵/리플레이에 박힌 맵 데이터"(플레이 시점에 고정된 사본)가 분리돼 있는 것과 같은 구조다.

## 배포(공유) 방식 — 아직 미정

"배포"가 정확히 어떤 동작인지는 아직 결정하지 않았다. 후보:

1. **유저 로컬 디스크에 JSON 파일로 다운로드**. 파일 안에 맵 UUID를 같이 저장해서 나중에 다시 가져올 때(재업로드) 원본과 매칭한다. 단점: 유저가 파일을 잃어버리거나 다른 기기에서 열면 데이터가 사라진 것처럼 보인다 — 이걸 유일한 저장소로 쓰기엔 위험하다.
2. **서버(우리 쪽)가 유저 계정 단위로 계속 보관**. 데이터 유실 위험은 줄지만, 지금은 로그인/백엔드가 없어서 당장은 구현할 수 없다.

지금 단계(백엔드 없음)에서는 `localStorage`가 실질적인 원본 저장소 역할을 계속 하고, "다운로드"는 백업·공유용 내보내기 정도로 취급하는 게 안전하다. 계정/DB가 생기면 그때 서버 저장으로 옮기는 게 맞다.
