# 맵 배포

## 이 문서를 볼 때

맵을 "배포"하거나 코드로 "공유"하는 기능을 만들거나 고칠 때 본다. 맵 자체의 방/오브젝트/상호작용 데이터 구조와 테이블은 [DB와 JSON 구조](./DATABASE_AND_JSON.md)를 참고한다.

## 작업본과 배포본

에디터에서 계속 고치는 대상과 플레이어가 하는 대상은 서로 다른 데이터다.

- **작업본**: 에디터가 저장하는 현재 상태(`map_room`, `map_object`, `map_door` 등). 저장할 때마다 덮어쓰고, 소유자만 볼 수 있다.
- **배포본**: 배포하는 순간의 작업본을 통째로 복사한 변경 불가능한 스냅샷(`map_release`). 플레이어는 항상 배포본만 읽는다.

작업본을 고쳐도 다시 배포하기 전까지 배포본은 바뀌지 않는다. 스타크래프트에서 편집 중인 맵 파일과 이미 게시된 맵 데이터가 분리돼 있는 것과 같은 구조다.

## 공개 범위는 두 가지

| 상태 | 의미 |
| --- | --- |
| 비공개 | 배포 전. 제작자만 접근한다. |
| 코드 공유 | 배포 후. **공유 코드를 아는 사람은 누구나**(비로그인 포함) 접근한다. |

공개 목록(누구나 둘러볼 수 있는 맵 목록)은 만들지 않는다. 맵이 많아지면 의미가 없어서이고, 나중에 "플레이 순위" 같은 기준이 생기면 그때 열기로 했다.

## 공유 코드

- 8자리 영문 대문자+숫자이고, 헷갈리는 글자(0/O, 1/I)는 뺐다(예: `K7M2QX4P`). 입력할 때 소문자도 허용한다.
- 첫 배포 때 맵에 한 번 붙고, 이후 **바뀌지 않는다.** 재배포하면 같은 코드로 최신 버전이 열리고, 공유를 중단했다가 다시 배포해도 같은 코드가 복구된다.
- 없는 코드, 형식이 틀린 코드, 공유가 중단된 코드는 모두 똑같이 404로 응답해서 존재 여부를 알아낼 수 없다. 조회는 IP당 분당 60회로 제한한다.

## 흐름

1. 제작자가 맵 목록에서 맵의 "수정"을 열고 **배포하기**를 누른다. (에디터를 나올 때 자동 저장이 나가고, 맵 정보 같은 메타 수정은 먼저 "저장"해야 배포본에 반영된다.)
2. 서버는 저장된 작업본을 읽어 검증한다: **시작 방이 있어야 하고, 그 방에 스폰 위치가 있어야** 한다. 아니면 이유와 함께 배포를 거절한다.
3. 통과하면 `version`을 하나 올려 스냅샷을 만들고(같은 맵의 동시 배포는 행 잠금으로 직렬화), 코드가 없으면 발급하고, `deploy = true`로 바꾼다.
4. 제작자가 코드를 복사해서 공유한다. 받은 사람은 방 만들기의 "최근 플레이 게임" 탭에서 코드를 입력해 맵을 추가한다.
5. **공유 중단**은 `deploy = false`로만 바꾼다. 코드와 배포본 기록은 남는다.

## API

| 엔드포인트 | 권한 | 동작 |
| --- | --- | --- |
| `POST /api/maps/:id/deploy` | 소유자 | 새 버전 스냅샷 생성 + 코드 발급. 응답 `{ shareCode, version }` |
| `DELETE /api/maps/:id/deploy` | 소유자 | 공유 중단 |
| `GET /api/shared-maps/:code` | 누구나 | 최신 배포본의 요약(제목, 난이도, 인원, 설명, 제작자 닉네임, 버전) |
| `GET /api/shared-maps/:code/layout` | 누구나 | 최신 배포본의 레이아웃 (실제 플레이 화면에서 쓸 것) |

## 아직 없는 것

- **실제 플레이 화면**: 게임방에 들어가 배포본을 불러와 진행하는 흐름은 게임방/세션 작업 때 만든다. 게임방은 시작할 때 `map_release.id`를 기억해 두어, 진행 중에 제작자가 재배포해도 그 방은 바뀌지 않게 할 예정이다.
- "배포 이후 수정됨" 같은 변경 표시.
- 맵을 클라이언트에 오래 저장하지 않는다. 브라우저에는 최근 플레이한 맵의 **코드만** 두고 내용은 매번 서버에서 받는다(레이아웃 JSON은 작고, 무거운 GLB는 브라우저 HTTP 캐시가 처리한다).
