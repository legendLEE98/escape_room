처음 프로젝트를 확인할 때는 이 순서로 읽으면 된다.

1. [게임 플레이](./GAMEPLAY.md)
   - 플레이어가 게임을 어떻게 시작하고, 무엇을 하며, 어떻게 탈출하는지 정리한 문서다.
2. [아키텍처](./ARCHITECTURE.md)
   - 프론트엔드, Three.js, 서버, nginx, Docker가 어떤 역할을 맡는지 정리한 문서다.
3. [DB와 JSON 구조](./DATABASE_AND_JSON.md)
   - 맵, 방, 오브젝트, 상호작용 데이터를 어디에 어떤 모습으로 저장하는지 정리한 문서다.
4. [맵 배포](./MAP_DEPLOY.md)
   - 맵 원본(draft)과 배포본을 어떻게 나누고, 배포를 어떤 방식으로 처리할지 정리한 문서다.

## 현재 상태

**구현됨**
- 맵 에디터: GLB 배치, 방 만들기(탑뷰 격자), 벽 자동 생성, 방 연결(문), 문 잠금(버튼·비밀번호), 오브젝트 부모-자식, 메모/선택지/버튼 상호작용, 플레이 테스트(클릭 이동 A*, 문 통과·열림 애니메이션).
- 계정: 이메일+비밀번호 회원가입/로그인(JWT 쿠키), 비밀번호 argon2 해시, 로그인 시도 제한. 맵 제작만 로그인이 필요하다.
- 맵 저장: 서버(PostgreSQL)에 저장하고 10초 자동 저장 + Ctrl+S. 맵은 만든 계정의 것이고 본인만 접근한다.
- 맵 배포: 배포하면 변경 불가능한 버전 스냅샷이 만들어지고 **공유 코드**가 발급된다. 코드를 아는 사람은 누구나(비로그인 포함) 조회할 수 있다. [맵 배포](./MAP_DEPLOY.md) 참고.
- 게임 시작 화면: 방 목록과 방 검색, 선택한 방의 정보 사이드바, 방 만들기 페이지("내 게임"/"최근 플레이 게임" 탭).
- 방 입장과 멀티플레이: 게임방은 서버(Redis)에 있어서 모두가 같은 방 목록을 보고, `입장하기`를 누르면 에디터 UI가 없는 게임 화면에서 고정 대기실이 열린다. 같은 방 사람들이 서로의 캐릭터·이름을 보고 움직임이 실시간으로 동기화되며(socket.io), 방장이 `게임 시작`을 누르면 모두에게 알려진다. 3D 장면의 공용 부품은 `src/engine/`으로 분리돼 에디터와 게임이 함께 쓴다. [아키텍처](./ARCHITECTURE.md) 참고.
- 인프라: PostgreSQL, Redis, NestJS 백엔드가 `compose.yaml`로 함께 실행된다.

**임시 상태**
- 최근 플레이한 맵은 브라우저 `localStorage`(공유 코드만 저장)에 있다.
- 게임 시작을 눌러도 아직 맵 플레이 화면으로 넘어가지 않고 "준비 중" 안내만 나온다.

**아직 없음**
- 게임 시작 이후의 맵 플레이 화면, 게임 진행 상태(열린 문·눌린 버튼·인벤토리)의 서버 공유.
- 구글·네이버 로그인, 이메일 인증/비밀번호 재설정, 인벤토리·열쇠 잠금, 이미지 상호작용(파일 업로드).
- 에셋 암호화 전달(DRM).
