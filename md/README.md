# Escape the Room 문서 안내

이 폴더에는 현재 게임을 만들 때 필요한 기준 문서를 정리해 둔다.

## 먼저 읽기

처음 프로젝트를 확인할 때는 이 순서로 읽으면 된다.

1. [게임 플레이](./GAMEPLAY.md)
   - 플레이어가 게임을 어떻게 시작하고, 무엇을 하며, 어떻게 탈출하는지 정리한 문서다.
2. [아키텍처](./ARCHITECTURE.md)
   - 프론트엔드, Three.js, 서버, nginx, Docker가 어떤 역할을 맡는지 정리한 문서다.
3. [DB와 JSON 구조](./DATABASE_AND_JSON.md)
   - 맵, 방, 오브젝트, 상호작용 데이터를 어디에 어떤 모습으로 저장하는지 정리한 문서다.
4. [맵 배포](./MAP_DEPLOY.md)
   - 맵 원본(draft)과 배포본을 어떻게 나누고, 배포를 어떤 방식으로 처리할지 정리한 문서다.

## 문서별 사용 시점

| 상황 | 먼저 볼 문서 |
| --- | --- |
| 게임 규칙이나 화면 흐름을 정할 때 | 게임 플레이 |
| 프론트엔드, 서버, 배포 작업을 할 때 | 아키텍처 |
| 테이블을 수정하거나 맵 저장 기능을 만들 때 | DB와 JSON 구조 |
| 맵 배포·공유 기능을 만들 때 | 맵 배포 |

## 현재 상태

- 쿼터뷰 이동과 GLB 캐릭터 표시가 구현되어 있다.
- 맵 에디터에서 GLB 에셋 배치, 방 만들기(탑뷰에서 격자 클릭/드래그로 바닥 그리기), 오브젝트 부모-자식 관계, 문/스폰 위치 같은 상호작용 설정까지 가능하다.
- 에디터는 방을 하나씩 격리해서 보여주고 편집한다 — 여러 방을 실제로 걸어서 이동하는 것은 아직 안 된다(맵을 배포할 때 방들을 연결해서 계산하는 로직은 미구현, [맵 배포](./MAP_DEPLOY.md) 참고).
- 프론트엔드는 React + Vite + Three.js를 사용한다.
- 맵 목록과 맵 안의 방/오브젝트 데이터는 지금 전부 브라우저 `localStorage`에만 저장된다. PostgreSQL은 Docker 컨테이너 설정(`compose.yaml`)만 준비돼 있고, 앱은 아직 여기 접속하지 않는다.
- 맵 저장 API, 로그인, 게임방, 멀티플레이는 아직 구현 전이다.
