# 게임 플레이

## 이 문서를 볼 때

게임의 화면 흐름, 퍼즐 방식, 아이템과 문 해금 규칙을 정할 때 본다. 테이블과 저장 형식은 [DB와 JSON 구조](./DATABASE_AND_JSON.md), 화면과 서버 구성은 [아키텍처](./ARCHITECTURE.md)를 참고한다.

## 게임 한 판의 흐름

```text
맵 목록
  → 게임방 생성 또는 참가
  → 인원 확인
  → 게임 시작
  → 3D 맵 탐색
  → 오브젝트 상호작용
  → 2D 모달에서 퍼즐 진행
  → 아이템 획득 또는 문 해금
  → 탈출 성공 또는 시간 초과
```

## 3D 맵과 2D 모달의 역할

3D 맵에서는 캐릭터를 움직이고, 방을 찾고, 상호작용할 오브젝트를 발견한다.

오브젝트를 클릭하면 같은 화면 위에 2D 모달이 열린다. 퍼즐과 상세 조작은 이 모달 안에서 진행한다. 모달이 열려 있는 동안에는 캐릭터 이동과 카메라 조작을 막는다.

```text
3D 맵에서 서랍 클릭
  → 화면 어두워짐
  → 서랍 2D 이미지와 입력창이 있는 모달 표시
  → 비밀번호 성공
  → 열쇠 획득
  → 모달 닫힘
  → 3D 맵 탐색 계속
```

## 이동과 충돌

캐릭터 이동은 별도 물리 엔진(Rapier, cannon-es 등) 없이 `Box3` 기반의 단순한 기하 계산으로 처리한다. Three.js 자체엔 물리 기능이 없고(`Box3`/`Raycaster` 같은 기하 유틸리티만 제공), 지금 필요한 수준(막힘, 밀림)은 이걸로 충분하다고 판단했다. 진짜 강체 물리(질량 보존, 회전, 연쇄 충돌)가 필요해지면 그때 캐릭터 이동 로직 전체를 물리 엔진 쪽으로 옮겨야 한다 — 지금 방식 위에 나중에 그냥 얹을 수 있는 건 아니다.

### 오브젝트 충돌 속성

| 필드 | 설명 |
| --- | --- |
| `blocksMovement` | 캐릭터가 못 지나가는지 여부 (boolean) |
| `colliderShape` | `box` \| `cylinder`. 사각형 가구는 box, 기둥/원형 오브젝트는 cylinder로 감싸서 판정한다. cylinder는 XZ 평면 수평 거리로 원-원 충돌 처리한다 (사각 바운딩 박스로 감싸면 모서리 부분에서 실제로 안 닿았는데 막히는 "가짜 충돌"이 생기기 때문). |
| `pushWeight` | 1~5. `blocksMovement`가 true인 오브젝트에만 의미 있음. 밀리는 정도를 나타낸다. |

### 밀기(push) 규칙

- 캐릭터에는 `pushStrength` 값이 있다.
- 캐릭터가 이동 방향에서 밀 수 있는 오브젝트(`pushWeight`가 있는 것)와 부딪히면, 그 방향으로 겹쳐 있는 오브젝트를 재귀적으로 체인으로 묶는다. 체인 중간에 안 밀리는 고정 오브젝트나 벽이 있으면 그 방향 이동 자체가 막힌다.
- 체인이 전부 밀 수 있는 오브젝트로만 구성되면, **체인 총 무게 = 포함된 오브젝트들의 `pushWeight` 합**이다. 예를 들어 무게 1짜리 오브젝트 둘이 겹쳐 있으면 체인 총 무게는 2가 된다.
- 캐릭터 이동 속도 배율은 `pushStrength / (pushStrength + 체인총무게)` 같은 감쇠 공식으로 계산해서, 체인이 무거울수록 캐릭터도 같이 느려지게 한다.
- 체인 총 무게가 `pushStrength`보다 훨씬 크면(예: 3배 이상) 무한히 느리게 밀리는 대신 완전히 막힘으로 처리한다.

### 알려진 엣지 케이스 (미해결)

동일한 오브젝트끼리 위치가 완전히 겹치면 분리 방향이 모호해져서 판정이 매 프레임 흔들리는(레이싱) 문제가 생길 수 있다. 대응 방향만 메모해 둔다 (자세한 설계는 나중에 다시 정리):

- 충돌 계산에서 Y축(높이)은 애초에 제외한다 — 캐릭터 이동은 XZ 평면 문제라 Y축이 분리 후보로 들어갈 이유가 없다.
- 오브젝트를 배치하거나 밀 때, 목표 위치가 다른 오브젝트와 완전히 겹치면 아주 작은 오프셋을 강제해서 애초에 완전 겹침 상태 자체를 안 만든다.
- 그래도 분리 벡터가 거의 0인 애매한 상황이 생기면, 매번 다시 계산하지 말고 오브젝트 `id` 비교 같은 결정론적 규칙으로 한쪽 방향을 고정한다.

### 구현 우선순위

방–방 연결(문)보다 이동 충돌(막힘/밀기)을 먼저 구현한다.

## 상호작용 예시

| 대상 | 모달에서 하는 일 | 결과 |
| --- | --- | --- |
| 서랍 | 비밀번호 입력 | 열쇠 획득 |
| 액자 | 이미지 확대와 단서 확인 | 숫자 단서 확인 |
| 금고 | 숫자 조합 맞추기 | 다음 아이템 획득 |
| 문 | 열쇠 보유 여부 확인 | 다음 방 이동 가능 |

## 모달 규칙

- 배경의 3D 화면은 남겨 두고 어둡게 보이게 한다.
- 모달 내부의 버튼, 이미지, 입력칸만 조작할 수 있다.
- 닫기 버튼과 `ESC` 키로 닫을 수 있다.
- 성공하면 아이템, 문 상태, 퍼즐 진행 상태를 게임방에 기록한다.
- 모달을 닫는다고 실패 처리하지는 않는다.

## 게임방 상태

맵 원본은 바꾸지 않는다. 플레이 중 바뀌는 정보는 게임방마다 따로 가진다.

- 현재 참여자
- 현재 방
- 획득한 아이템
- 열린 문
- 푼 퍼즐
- 시작 시간과 남은 시간

이 정보는 나중에 게임 세션 테이블과 실시간 서버에서 관리한다.
